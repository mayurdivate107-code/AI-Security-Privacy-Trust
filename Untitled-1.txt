================================================================================
- Crop Taxonomies:
  * Cereals & Millets: Rice (Paddy), Wheat, Maize (Corn), Sorghum (Jowar), Pearl Millet (Bajra), Barley, Finger Millet (Ragi).
  * Pulses & Legumes: Chickpea (Gram), Pigeon Pea (Tur), Red Lentil (Masoor), Black Gram (Urad), Green Gram (Moong), Soybean.
  * Commercial & Cash Crops: Cotton, Sugarcane, Jute, Tobacco.
  * Oilseeds: Mustard/Rapeseed, Groundnut (Peanut), Sunflower, Sesame, Safflower.
  * Horticulture & Vegetables: Tomato, Potato, Onion, Eggplant (Brinjal), Chili Pepper, Okra (Ladyfinger), Cabbage, Cauliflower, Cucumber.
  * Fruit Crops: Mango, Banana, Citrus (Orange/Lemon), Pomegranate, Guava, Apple, Grapes, Papaya.
  * Spices & Plantations: Turmeric, Ginger, Black Pepper, Cardamom, Coffee, Tea.
- Soil Types:
  * Alluvial (High natural fertility, rich in potash and humus, responsive).
  * Black Cotton Soil / Regur (High montmorillonite clay, moisture-retentive, cracks when dry).
  * Red & Yellow Soil (Iron-oxide rich, porous, needs phosphorus and nitrogen supplementation).
  * Laterite Soil (Heavy leaching in tropical rains, acidic, low organic content).
  * Arid & Desert Sandy Soil (Rapid percolation, low nutrient holding, requires drip fertigation).
  * Loamy Soil (Optimal balance of sand, silt, and clay; ideal agricultural baseline).
  * Saline & Alkaline / Sodic Soil (High electrical conductivity / exchangeable sodium, requires gypsum and drainage).
- Agro-Climatic Seasons:
  * Kharif (Monsoon / Autumn: June - October).
  * Rabi (Winter / Spring: October - April).
  * Zaid (Summer / Irrigated: March - June).
  * Temperate Continental Seasons (Spring, Summer, Autumn).
- Farming Philosophies:
  * Conventional (Precision synthetic inputs, chemical disease suppression).
  * Certified Organic (Bio-fertilizers, botanicals, Trichoderma, Pseudomonas, cow-dung based preparations).
  * Regenerative Agriculture (Cover crops, minimum tillage, biochar integration).
  * Integrated Pest & Nutrient Management (IPNM) (Biological priority backed by targeted synthetic emergency controls).

9. FORM & ADVISORY CONFIGURATION

The application requires 4 deterministic intake forms with strict validation:

1. Farm & Plot Registration Form:
   - `farm_name`: string, min 3 chars.
   - `location_name`: string (e.g., "Fresno County, CA" or "Nashik, Maharashtra").
   - `latitude`: optional number (-90 to 90).

   - `total_area`: positive number.

   - `soil_type`: enum (matches Section 8 soil types).
   - `water_source`: enum ("borewell", "canal", "river", "rainfed", "municipal").
   - `irrigation_type`: enum ("drip", "sprinkler", "flood", "furrow", "rainfed").

2. Crop Selection & Advisory Request Form:
   - `plot_id`: UUID (foreign key).
   - `season`: enum ("kharif", "rabi", "zaid", "spring", "summer", "autumn", "winter", "year_round").
   - `target_crop`: optional string (if empty, AI recommends top 3 crops).
   - `farming_method`: enum ("conventional", "organic", "regenerative", "integrated").
   - `budget_tier`: enum ("low_cost", "moderate", "commercial_intensive").
   - `target_sowing_date`: date string (YYYY-MM-DD).

3. Visual Pathology Diagnostic Form:
   - `plot_id`: optional UUID.
   - `crop_name`: string, required.
   - `crop_age_days`: optional integer.
   - `affected_part`: enum ("leaf", "stem", "fruit", "root", "whole_plant").
   - `observed_symptoms`: array of strings (e.g., "yellowing", "brown_spots", "wilting", "curling", "holes", "white_mildew").
   - `image_file`: binary file (JPEG/PNG/WEBP, max 5MB).

4. Soil Test Parameter Form:
   - `plot_id`: UUID, required.
   - `nitrogen_ppm`: number (available N in mg/kg or kg/ha).
   - `phosphorus_ppm`: number (available P in mg/kg or kg/ha).
   - `potassium_ppm`: number (available K in mg/kg or kg/ha).
   - `ph_level`: number (scale 0.0 - 14.0).
   - `organic_carbon_percent`: number (scale 0.0% - 10.0%).
   - `electrical_conductivity`: number (dS/m).
   - `target_crop`: string, required.

11. ROW LEVEL SECURITY (RLS) / DATA ISOLATION RULES
================================================================================
Enforce strict multi-tenant isolation via PostgreSQL Row Level Security:

```sql
-- Enable RLS on all domain tables
ALTER TABLE public.profiles ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.farms ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.plots ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.crop_advisories ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.disease_diagnostics ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.soil_tests ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.chat_conversations ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.chat_messages ENABLE ROW LEVEL SECURITY;

-- 1. Profiles Table Policies
DROP POLICY IF EXISTS "Users can view own profile" ON public.profiles;
CREATE POLICY "Users can view own profile" 
ON public.profiles FOR SELECT 
USING (auth.uid() = id);

DROP POLICY IF EXISTS "Users can update own profile" ON public.profiles;
CREATE POLICY "Users can update own profile" 
ON public.profiles FOR UPDATE 
USING (auth.uid() = id);

-- Trigger: Automatically populate public.profiles upon auth.users signup
CREATE OR REPLACE FUNCTION public.handle_new_user()
RETURNS TRIGGER AS $$
BEGIN
  INSERT INTO public.profiles (id, full_name, email, role)
  VALUES (
    NEW.id,
    COALESCE(NEW.raw_user_meta_data->>'full_name', 'Agricultural Producer'),
    NEW.email,
    'farmer'
  );
  RETURN NEW;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

DROP TRIGGER IF EXISTS on_auth_user_created ON auth.users;
CREATE TRIGGER on_auth_user_created
  AFTER INSERT ON auth.users
  FOR EACH ROW EXECUTE PROCEDURE public.handle_new_user();

-- 2. Farms Table Policies
DROP POLICY IF EXISTS "Users manage own farms" ON public.farms;
CREATE POLICY "Users manage own farms" 
ON public.farms FOR ALL 
USING (auth.uid() = user_id) 
WITH CHECK (auth.uid() = user_id);
```

12. BACKEND API ROUTES
================================================================================
All endpoints reside under `/api/v1` and require an `Authorization: Bearer <Supabase_JWT>` header, which is verified by the `verifyAuth` middleware.

### A. Farm & Plot Management
1. `GET /api/v1/farms`
   - Description: Retrieves all farms belonging to the authenticated user with aggregated plot counts.
   - Response: `200 OK` -> `[ { id, name, location_name, total_area, area_unit, plots_count, created_at } ]`
2. `POST /api/v1/farms`
   - Description: Registers a new farm holding.
   - Body: `FarmSchema` validation.
   - Response: `201 Created` -> `{ id, ...farmData }`
3. `GET /api/v1/farms/:id`
   - Description: Fetches detailed farm record including an array of its associated plots.
   - Response: `200 OK` -> `{ id, name, plots: [ { id, plot_name, size, soil_type, irrigation_system, current_crop } ] }`
4. `POST /api/v1/farms/:id/plots`
   - Description: Appends a new plot to an existing farm.
   - Body: `PlotSchema` validation.
   - Response: `201 Created` -> `{ id, farm_id, ...plotData }`
5. `GET /api/v1/plots/:id`
   - Description: Retrieves single plot metadata with active advisories and soil records.

### B. AI Crop Advisory Engine
1. `POST /api/v1/advisory/recommend-crops`
   - Description: Evaluates plot soil baseline, climatic season, and budget tier to return 3 highly feasible crops.
   - Body: `{ plot_id: string, season: string, budget_tier: string, farming_method: string }`
   - Response: `200 OK` -> `{ recommendations: [ { crop_name, rationale, expected_yield, water_need, market_outlook } ] }`
2. `POST /api/v1/advisory/generate-plan`
   - Description: Generates a complete, stage-by-stage lifecycle cultivation calendar.
   - Body: `CropAdvisoryRequestSchema` validation.
   - Action: Queries plot details, executes Gemini 2.5 Flash with `cropLifecycleResponseSchema`, persists to `crop_advisories`, returns saved object.
   - Response: `201 Created` -> `{ id, crop_name, lifecycle_stages: [...], risk_factors: [...] }`
3. `GET /api/v1/advisory/:id`
   - Description: Retrieves a saved advisory plan.
   - Response: `200 OK` -> Full `crop_advisories` record.

### C. Visual Pest & Disease Diagnostics
1. `POST /api/v1/diagnostics/analyze`
   - Description: Multi-modal plant pathology diagnosis from leaf/stem imagery.
   - Headers: `Content-Type: multipart/form-data`
   - Form Data: `image` (binary, max 5MB), `crop_name` (string), `affected_part` (string), `observed_symptoms` (JSON string or comma-separated), `plot_id` (optional UUID).
   - Middleware: `multer.single('image')`, `verifyAuth`.
   - Action: Uploads buffer to Supabase Storage bucket `crop-diagnostics`, sends image base64 inline data + prompt to Gemini 2.5 Flash with `diseaseDiagnosticResponseSchema`, persists to `disease_diagnostics`, returns report.
   - Response: `200 OK` -> Full diagnostic record with organic and synthetic remedies.
2. `GET /api/v1/diagnostics/history`
   - Description: Retrieves past diagnostics performed by the user.
3. `GET /api/v1/diagnostics/:id`
   - Description: Fetches detailed diagnostic report.

### D. Soil Analysis & Fertilizer Dosing
1. `POST /api/v1/soil/analyze`
   - Description: Evaluates NPK, pH, and Organic Carbon to generate tailored commercial and organic fertilizer dosages.
   - Body: `SoilAnalysisRequestSchema` validation.
   - Response: `201 Created` -> Persisted `soil_tests` record with deficiencies, pH advice, and commercial/organic dosage schedules.
2. `GET /api/v1/soil/plot/:plot_id`
   - Description: Retrieves soil testing history and trends for a specific plot.

### E. Agronomic Copilot (Chat)
1. `POST /api/v1/chat/conversation`
   - Description: Initiates or resumes a consultation session.
   - Body: `{ plot_id?: string, title?: string }`
   - Response: `200 OK` -> `{ conversation_id: string }`
2. `POST /api/v1/chat/message`
   - Description: Sends a query to the Agri-Copilot.
   - Body: `ChatMessageRequestSchema` validation (`{ conversation_id, message }`).
   - Action: Loads recent 10 messages from DB, loads user's active farm and plot context, prompts Gemini 2.5 Flash with system instructions, stores user & assistant messages, returns response.
   - Response: `200 OK` -> `{ reply: string, created_at: string }`
3. `GET /api/v1/chat/:conversation_id/messages`
   - Description: Retrieves full chat history for the conversation.

   - Enable `helmet()` on the Express application to set secure HTTP headers (XSS Filter, HSTS, Sniffing protection).
   - Configure strict `cors()` restricting access solely to the authorized frontend domain.
   - Apply rate limiting via `express-rate-limit`:
     * Standard API routes: 100 requests per 15-minute window per IP.
     * AI generation endpoints: 20 requests per 15-minute window per IP/user.
4. Injection Defense:
   - 100% of incoming payloads must be parsed and sanitized with Zod schemas.
   - Use parameterized PostgreSQL queries via the Supabase client to prevent SQL injection.
